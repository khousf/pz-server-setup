# Project Zomboid服务器：几人开服买什么配置、端口怎么放行、Mod 怎么同步，一篇讲清楚

搜“Project Zomboid 服务器”的人基本分两种。一种还没开服，卡在第一步：我和三个朋友联机，到底要不要买服务器，买多少内存才不卡。另一种服已经开了，在找毛病：进不去、Mod 报错、人一多就掉帧。这两种问题的答案其实在同一张纸上——先搞清楚 PZ 服务端到底吃什么资源，后面每一步都好办了。

## 先别按核心数买：PZ 吃的是单核和内存

Project Zomboid 服务端是 Java 写的，主循环基本跑在单线程上。僵尸寻路、天气、载具物理、区块更新，全都在抢同一个每 tick 的预算。所以一台 32 核 2.5GHz 的机器，跑起 PZ 来反而可能不如 6 核 4.5GHz 的那台。租服务器看到“现代 Xeon/EPYC”这种不带型号的描述，直接问对方具体型号，主频比核心数重要得多。

内存才是真正的门槛，而且它跟“开服多久”强相关。服务端按区块把地图常驻在内存里，一个跑了两个月、探索过半个 Knox County 的存档，吃内存的量远超同人数的开荒新档。玩家分散在不同城镇，同时加载的区块也更多——四个人挤在一个安全屋，比四个人分别在四个镇，省内存得多。

第三方整理出来的经验值大致是这样：8–10GB 是多人生存的现实下限；Build 42 相比 B41 在同样人数下要再加 2–4GB；粗算下来每人在线约 500MB。硬盘方面，开服文件本身不到 2GB，但 Mod、自定义地图和存档会把它撑到 10GB 以上，而且存档是成千上万个小区块文件在持续读写，NVMe 和普通 SSD 的差距在人多、开车跑图的时候能明显感觉到。带宽上行 5Mbps 是最低线，不是舒服线。

## 按人数对号入座

| 规模 | 参考内存 | 单核频率 | 存储 | 说明 |
| --- | --- | --- | --- | --- |
| 2–4 人，原版 | 4GB 起，6–8GB 更稳 | 3.5GHz+ | 20GB SSD | 自家电脑也扛得住 |
| 5–8 人，轻量 Mod | 8–12GB | 4.0GHz+ | 30GB NVMe | 建议上云 |
| 10–20 人，大量 Mod | 16–24GB | 4.5GHz+ | 50GB NVMe | 地图 Mod 是内存黑洞 |
| 32 人公开服 | 32GB+ | 4.5–5.0GHz | 80GB+ NVMe | 最好别跟别人挤 CPU |

这是从多个开服指南里交叉出来的经验区间，不是官方硬性要求。所以要提醒一句：一份挂了大量地图 Mod 的 8 人服，吃内存很可能超过原版 16 人服。地图 Mod 给的是全新的区块网格，加一张就等于让服务端多常驻一整套地形数据。

Build 42 的多人状态需要你自己确认一下。B42 多人是从 2025 年底开始挂到 unstable 分支的，不同资料对稳定时间说法并不一致——有的写到 42.20 已经转稳定，有的在 2026 年 3 月仍然说官方没给出稳定版时间表。开服前先看一眼当前分支状态，别照着一篇半年前的教程直接跑。官方目前的公开建议是，压力测试阶段把 B42 多人数控制在 20 人以内；实际体验上，超过 10–15 人开始碰运气。

## 自建还是租：判断线其实很简单

家用电脑开服的特点是免费、完全可控，代价是它必须一直开着，上行带宽通常是最先撑不住的那一环，路由器端口转发出问题是最常见的卡点，而且家宽 IP 会变，朋友存好的服务器地址哪天就连不上了。如果运营商给你的是 CGNAT 内网地址，那从公网根本连不进来，只能绕隧道。

租服务器的好处很直白：有固定公网 IP、开机就能用、上行带宽不用跟家里的视频流抢。代价就是月租，加上你不能像自己家用电脑那样随便插块硬盘。

那条线大概在这儿：三个朋友每周玩两晚，自家电脑完全够。一旦你在意“我睡了世界还在跑”，租就比自建便宜了。

## 从零开服：Linux 上的正经流程

服务端文件走 SteamCMD，App ID 是 `380870`，用匿名登录即可，不需要买过游戏。

1. 加 32 位支持库（SteamCMD 是 32 位程序），把 `screen`、`curl`、`wget`、`tar` 装上。
2. 建一个非 root 的专用账号。别拿 root 跑游戏服，这是习惯问题，不是洁癖。
3. 下载 SteamCMD，用 `force_install_dir` 指定安装目录，然后 `app_update 380870 validate` 把服务端拉下来。
4. 先跑一次。第一次启动会生成配置文件并要你设置管理员密码，设完就关掉。
5. 改配置。注意配置文件不在安装目录里，而是在用户目录的 `Zomboid/Server/` 下面，默认三个文件：`servertest.ini`（服务器名、密码、端口、人数上限、Mod）、`servertest_SandboxVars.lua`（僵尸密度、物资稀有度、经验倍率）、`servertest_spawnregions.lua`（出生区域）。
6. 用 systemd 把它包起来，崩了自动重启，开机能自启。
7. 放行防火墙端口（下面细说）。

Windows 路径更省事：双击 `StartServer64.bat` 就跑，适合不想碰命令行的服主。雨云的游戏云产品支持 Windows 和 Linux，系统可以随时重装，所以这一步选错了也不至于重买。

> 一个几乎人人踩过的坑：服务端运行中编辑 `servertest.ini`，关机时配置文件会被覆盖，你的改动悄无声息地消失。改配置之前先停服。

日常运维还有两条：把 `PauseEmpty` 打开，没人在线时世界不烧 CPU；以及每 12–24 小时重启一次，Java 的内存占用会慢慢往上爬，计划内重启总好过半夜崩服。

## 端口放行：两套防火墙都得开

| 端口 | 协议 | 用途 |
| --- | --- | --- |
| 16261 | UDP | 主游戏端口 |
| 16262 起 | UDP | 玩家直连，部分版本每个槽位占一个 |
| 8766–8767 | UDP | 旧版本的 Steam 查询与发现 |
| 27015 | TCP | RCON 远程管理（可选） |

在云服务器上开服，宿主系统的防火墙（`ufw`、`firewalld`）和云平台这一侧的安全组是两回事，两边都要放，只开一边的表现是“内网能连、外面连不上”。如果买的是 NAT 机型，还得在控制面板里把端口映射配上——PZ 实际要用的端口不多，几个映射位就够。

RCON 别直接暴露在公网上，它默认不加密，用 VPN 或者 SSH 隧道走。

## Mod 报错的真正原因

服务端配置里有两行管 Mod，它们填的不是一个东西：

- `WorkshopItems=` 填数字 ID，也就是创意工坊链接里那串数字。
- `Mods=` 填 `mod.info` 里的 `mod_id`。

填反、混填、依赖项顺序不对，服务端都起不来。分号分隔，被依赖的放前面。

除此之外还有几条经验值得照做：所有玩家必须订阅完全一致的 Mod 列表，差一个就是秒断；每次加 Mod 两三个，重启验证一遍再加下一批，别一次性丢十二个进去；装或删地图类 Mod 之前先备份存档，中途删大 Mod 有可能把区块写坏。

## 挑主机时该盯的几个参数

先把不看的东西划掉：核心数、“现代处理器”这种模糊描述、前台宣传的“每人每月几块钱”的槽位价——PZ 没有硬槽位这回事，它吃的是内存和单核，按槽位定价是营销惯性。

要看的是这些：

- **单核主频和具体型号**，能报出型号的商家至少敢让你比。
- **能不能原地升配**。PZ 服的内存需求是会长的，不能原地升配意味着每次加内存都要重装重建。
- **备份策略**：多久一次、保留多久、能不能自助还原、能不能下载到本地。存档里是几百小时的进度，同盘备份不算备份。
- **端口数量**：你要几个映射位。
- **试用和退款政策**。

雨云在这几点上的公开信息比较完整：2018 年成立，KVM 虚拟化，支持 Windows 和 Linux，游戏云线主打高主频 CPU，型号是公开的——i9 14900KF、i9 13900KF（屏蔽小核、水冷超频）、Ryzen 9950X / 7950X / 5900X、Gold 6146、E5 2666v3、EPYC 7A23 这些。线路走京东云 BGP，官方游戏云页面写的是 150G DDoS 物理防御，各地机房的防御规格会不一样。产品形态分三种：游戏云 VPS（独立 IP 可选，NAT 机型默认给 15 个端口映射，可以加购独立 IP）、雨云自研面板、MCSM 面板。

这里有个选择判断：面板那两条线更偏向 MC 那类常见服务端的一键开服，而 PZ 需要你自己用 SteamCMD 装、Mod 用创意工坊 ID 手工同步，所以我建议开 PZ 服直接选 VPS，版本和 Mod 的控制权全在自己手里，出了问题也知道去哪儿看日志。官方页面还提到购买产品有 10% 以上积分返利，积分能提现或换优惠券。

## 固定计费还是动态计费，PZ 服主怎么算

雨云游戏云有两种计费方式，这是长期开服时最影响账单的一个选择。

固定计费就是常规月付。动态计费则是低基础月租加上按 CPU 超额使用率日结的“电量”：CPU 使用率基准值是 20%，低于 20% 不算耗电，超出的部分按电量单价计费。电量单价跟机型走——E5 2666v3 是 0.0005 元/电量，Gold 6146 和 Platinum 8275cl 是 0.0006 元，Ryzen 5900X 是 0.0008 元，9950X / 7950X / 13900K / 14900K 是 0.001 元。

拿 PZ 套一下这个规则就很清楚了：只要服务器上有人在跑图、被僵尸追，CPU 占用长期压在 20% 以下基本不可能。雨云论坛里有位用户贴过自己 MC 生存服的账，3 人在线一天烧掉约 1000 电量、折合每月 30 元左右，最后他自己的结论是固定计费更划算。PZ 的负载特性跟生存服接近，所以长期服建议直接选固定计费；动态计费适合只在周末开几个小时、平时把服关掉的小团体。

## 几个被问得最多的问题

**PZ 服务器要多少内存？**
原版 2–5 人 4–6GB 起步，8–10GB 是多人生存的现实下限，B42 在同样人数上再加 2–4GB。Mod 数量和地图探索进度对内存的影响比人数还大。

**4 核够吗？**
看频率不看核数。PZ 主循环单线程，两颗 4.5GHz 的核比八颗 2.5GHz 的核更适合它。

**要不要独立 IP？**
NAT 机型默认给 15 个端口映射，PZ 用的端口不多，够用。要对外发布公开服或者同时开多个服，再考虑加购独立 IP。

**朋友能不能只买一份服务器一起分摊？**
可以，也更常见。一个服务端实例就能容纳所有玩家，不需要每人一套。

**面板服能不能开 PZ？**
面板产品更擅长 MC 那类常见服务端的一键部署。PZ 建议选 VPS 自己装，Mod 用创意工坊 ID 手工同步，出问题时日志位置和配置路径都是你熟悉的。

最后一句实在话：开 PZ 服最贵的成本不是月租，是存档丢了。不管选哪家，先把异地备份跑通，再往 Mod 列表里加东西。
